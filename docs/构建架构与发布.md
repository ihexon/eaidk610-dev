# EAIDK610 完整 Armbian 镜像构建架构

项目改为直接使用官方 `armbian/build` 生成完整镜像。框架以 Git submodule
固定，本仓库不修改 submodule 内容；EAIDK610 board 定义、内核补丁、U-Boot
补丁和镜像定制全部位于根目录 `userpatches/`。

当前固定的 Armbian 提交为
`66dbc7af2a77d52ccd3fe2156a55687622848ea3`。该快照的 rockchip64 edge 是
Linux 7.2 稳定分支；构建时解析并记录 `linux-7.2.y` 的具体提交。U-Boot
固定为已经在 EAIDK610 实机启动成功的 upstream `v2026.10-rc3`，使用
`eaidk-610-rk3399_defconfig`。为复用已经实机启动成功的组合，采用 U-Boot
主线 TPL/SPL、Rockchip BL31 v1.36 和 upstream binman 生成的
`u-boot-rockchip.bin`。Armbian 将这个完整启动固件写到镜像 LBA 64，其内部
U-Boot FIT 位于 LBA 16384，不再下载其它板卡镜像后进行二次替换。

## 活动补丁

- `userpatches/kernel/archive/rockchip64-7.2/` 在完整 Armbian Rockchip
  补丁栈之外追加 EAIDK610 的 FUSB302 Try.Source 修复。
- `userpatches/u-boot/eaidk610-v2026.10-rc3/` 是 U-Boot 专用补丁入口；当前
  使用未修改的上游版本。
- `userpatches/overlay/boot/overlay-user/` 保存项目维护的板级 overlay 源码。
  其中 Type-C USB2/供电部分已经在 7.1 实机验证；2026-09-07 新增的
  `tcphy0` extcon、耳机检测和扬声器放大器描述仍需在新镜像上验证。构建前
  重新编译 DTBO，镜像定制脚本安装并默认启用它。

现有 overlay 依赖 Armbian 的 `typec-extcon`、`extcon,ignore-usb` 和 DWC3
reset quirk，不能脱离 Armbian Rockchip 补丁栈使用。overlay 还把 bridge
接到 `tcphy0`，让 RK3399 USB3 PHY 获得角色和插头方向；音频部分把
GPIO4_D4 以 active-high 耳机检测接到 simple-audio-card，并用
`simple-audio-amplifier` 管理 GPIO0_B3 和 PT5305。Linux 7.2 第一次完整镜像
仍必须通过离线 DT 合并和实机回归确认。

## 构建和校验

正式编译前只检查成本低且能给出确定结论的项目输入：submodule 和 edge
版本、board/U-Boot 配置、必要内核配置、patch 与 overlay 哈希、overlay 编译、
镜像定制脚本以及 runner 架构和磁盘。Linux 提交由构建脚本解析一次，并直接
传给正式 `compile.sh build`；FUSB302 patch 由 Armbian 在真正编译前的标准
patch 阶段校验并应用，不再额外启动一次 `config-dump` 构建环境，也不依赖
可能暂时滞后的 GitHub Linux 镜像。

构建允许使用 Armbian 标准 artifact cache。Armbian 的 kernel artifact key
包含 Linux 提交、`userpatches` patch 和内核配置哈希，因此缓存命中不会把
未打补丁的官方内核误当成本项目内核；没有匹配项时仍会正常从源码编译。

发布前检查最终镜像前 16 MiB 的 U-Boot、分区边界、board 标识、edge 内核
与模块、EAIDK610 DTB、已启用的 Type-C DTBO，并用镜像内最终 DTB 实际执行
`fdtoverlay`，核对 managed regulator、Source 偏好、1.5A 声明、`tcphy0`
extcon、active-high 耳机检测和 speaker amplifier。全部通过才创建 GitHub
pre-release。发布判断不依赖 Armbian 日志的排版或展示文本；
发布前只检查最终镜像的关键内容。

失败时只上传构建日志和 Armbian 诊断，保留 1 天；不再花时间压缩和上传一张
未通过校验的完整镜像。正式成功产物使用 XZ level 6 压缩后发布到 GitHub
Release，不受 Actions 工件保留期影响。Release 只附带镜像、`SHA256SUMS`
和构建清单；发布说明直接作为 Release 正文，不重复上传为附件。压缩数据通过
标准输出写入 runner 临时文件再原子改名，避免 XZ 尝试复制 Docker 产物保留
的 root 组属性而产生权限错误。

已验证的 7.1.8 kernel-only r1 位于 `archive/kernel-r1/`；板端脚本位于
`scripts/board/`；旧二进制和日志位于被忽略的 `local/`；供应商 PDF 位于
被忽略的 `references/`。kernel-only workflow 仅作为历史复现资料保留，活动
workflow 不会再次单独发布一套内核；完整镜像中的 kernel 只由一次 Armbian
image build 产生或按精确 artifact key 获取。
